原手册的历史“本轮允许”和可直接发送给Codex的启动提示不作为本次执行指令迁入。若日后需要新验收，先由用户另行确认目标仓库、确切源码SHA、资源、资产、执行范围和回传方式，再使用当前正式主库的完整流程；不要直接照历史授权启动。

## 新验收前必须明确的条件

1. 核对目标私库、分支、源码提交和操作者真实身份；正式主库验收使用独立 `codex/windows-acceptance-*` 分支和PR，不直接推送或合并main，不把副本同步提交当作主库验收。
2. 真实Windows、64位Python3.11、uv、Node及目标浏览器需可用。原流程按Edge采集工具信息，历史已接受结果来自Chrome；新验收必须明确浏览器及相应证据，不能混写。
3. 从明确提交导出到中文含空格的新目录，证据目录放在源码目录外。记录源码ZIP哈希，逐文件核验版本绑定；依赖按原uv.lock安装，不重锁。首次失败、最小修复和最终全新导出复验分开记录。
4. 资产按 `configs/windows-assets.json` 核对，教师资源信息见 `configs/teacher-assets.json`；清单不是数据或权重。来源与同组/教师传递范围见[数据许可](DATA_LICENSE.md)，保留模型卡与许可，不冒称接收者重新申请下载。
5. 副本目前缺少 ui/project-data.json、ui/demo-cases.json 和两张实验SVG。采集器会将缺失资产记为BLOCKED；不得用生成占位数据或改哈希清单绕过。制作脚本依赖未共享证据，不自动运行以补齐展示。

## 工具能力与真实证据

`scripts/windows_acceptance.py` 保留现有 init、run、assets、cpu、record、finalize 命令。init绑定源码及环境；run可实际启动依赖安装、准备数据或测试；cpu读取已完成的新预测并独立计数；record保留操作者声明和证据路径；finalize检查缺项并生成证据包。这些命令会读写真实文件或启动进程，本次均不执行。

未来经授权的检查应覆盖：

| 检查 | 所需实际依据 |
|---|---|
| 实时抽取与方法对比 | 新合成文本、D0/N0/N1真实结果、Unicode跨度与嵌套；无参考输入不计算伪造准确率，不勾选API |
| 错误与实验页 | 参考/历史预测/路线来源、切换后旧结果失效、曲线/阈值/图表资源；缺项如实保留 |
| JSON导出 | 浏览器实际保存合成短文JSON后，从磁盘读回原文、方法、实体、状态与来源，保留真实文件和截图 |
| 任务并发与取消 | 忙碌响应、归属进程及全部后代退出；其他任务与服务保留，Job Object归属失败时不启动推理 |
| 刷新、中断与恢复 | 同一job ID恢复、不生成重复任务；中断后旧任务不显示通过；未核清所属进程时不删保护锁 |
| 完整CPU复现 | 单独的新完成任务，D0/N0/N1各5000条新预测；取消/中断任务不能冒充最终通过 |

独立核算核对冻结金标哈希、5000个唯一ID、文本/顺序、Unicode坐标及类型，重新计算TP/预测数/参考数和P/R/F1，与 `configs/reproduction-expected.json` 精确值比较。历史F1为38.0192%／60.2793%／66.8942%，不是本轮新成绩。差异、缺资产和失败均保留，不改模型、阈值、金标或期望值使其通过。

## 回传与状态更新

未来主库验收回传PR链接、脱敏报告、独立证据ZIP及SHA-256、未完成/失败清单。报告写明实际操作者、Codex执行和真人操作范围、被验收SHA、源码哈希、环境、检查状态、首轮失败/修复/新复验及预测哈希。测试模拟不算真实API联通，截图不替代下载读回或进程检查。

数据、权重、密钥、账本、完整预测和原始医学文本不进入证据ZIP；保留在受控本机。环境及session可能含私人路径，先逐项脱敏检查，不自动上传Git、Issue、PR附件或公共服务。

只有接收方独立核对真实证据后才能更新对应源码的Windows状态。原始手册、两份历史验收报告和证据原件仍在主库，本批不提供，不把上述流程参考当作已执行证明。视频、分享链接、真人复核及课程正式提交仍见[待办](待人工完成清单.md)。
